# Farm Stand — project instructions

- Build a new farm-themed website-services showcase, not a produce business.
- User-approved concept: sunlit stand; excellent real imagery; restrained spatial depth; usable farm-shop demo.
- “Farm Stand” is a working label. No exact scene, brand, copy, or rendered baseline is approved yet.
- Do not restore, read through, or rebuild the cancelled Living Engraving project.
- User changes override design defaults. Permission boundaries still apply.
- Follow this pack for the new project, not old M1/M2 stop rules.

## Working method
- Inspect existing new-project work before editing; preserve unrelated changes.
- Reuse licensed assets and suitable code before generating or rebuilding.
- A beautiful photograph or render is preferable to a poor procedural substitute.
- Asset quality and composition are requirements, not deferred polish.
- Keep source assets separate from optimized derivatives; record provenance.
- Codex owns implementation and integration. Existing Hermes/tools are optional support.
- Delegate only bounded independent tasks; do not install another agent framework.
- Keep one shared state writer. Workers return findings rather than competing doc edits.
- Make local, reversible implementation choices within the approved direction.
- Do not stop at planning or require user review after every internal comparison.

## Product and visual rules
- State that the actual service is websites for growers/local businesses near the opening.
- Clearly identify the produce/pickup interaction as a demonstration.
- No real orders, payments, fake availability claims, testimonials, metrics, or certifications.
- No false email/submission success; keep unspecified business configuration unconfigured.
- No liquid glass, generic three-card service section, decorative slogans, cursor tricks, or forced intro.
- One principal setting and signature transition. No miniature farm simulator.
- Use real HTML for text, controls, and enquiry content.
- Preserve native scrolling, keyboard access, reduced motion, and an attractive non-WebGL path.
- No arbitrary geometry, photographic, or asset-quality regression to make a test pass.

## Technical discipline
- Default stack: React + TypeScript + Vite, Anime.js, and a small Three.js scene.
- Check compatible actual versions; commit one lockfile. Do not copy stale API snippets.
- Do not add GSAP/Lenis/Framer Motion/R3F by default or run competing animation owners.
- Project-local required dependencies and licensed free asset downloads are in scope.
- No sudo, global config edits, paid services, purchases, credential changes, or unrelated infrastructure changes.
- Standing project authorization permits repository commits, safe integration into `main`, pushes to `Denoax/farm-stand`, and its existing GitHub Pages deployment after the complete integrated tree passes the required checks.
- Verify actual rendered pixels; tests and captured files do not prove visual quality.
- Report production transfer, viewport, renderer and acceleration separately from test results.
- Never describe software-rendered recordings as hardware performance evidence.
- Do not silently promote snapshots to accepted baselines.

## Delivery
- For completed website work, follow: implement → inspect → test → commit → integrate into current `main` → push `main` → verify the associated Pages run → verify the live HTTPS website.
- Do not stop at a local preview or “ready for deployment” report unless the user explicitly requests local-only work. Publish coherent verified change sets, not temporary experiments or every file save.
- Failed checks block publication. Do not bypass branch protection, force-push, discard newer work, weaken tests, or treat deployment as artistic approval.
- Keep `.github/workflows/deploy-pages.yml`, the `/farm-stand/` base path, and GitHub Pages unless the user explicitly changes that infrastructure decision.
- Keep state and the few important open defects current; do not create a sprawling register.
- Preserve historical reports. Add or update the task-relevant review summary, selected captures, and honest motion evidence when the scope calls for them.
- Identify exact source state and uncommitted changes; user retains artistic approval.
- Report a precise blocker and continue independent work where useful; never invent completion.
